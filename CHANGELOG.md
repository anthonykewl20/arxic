### security

- 1.0-RUN-INPUT-FINGERPRINT (#176): fail closed when a reused orchestrator run id has changed semantic inputs, an unprovable legacy record, or drifted persisted artifact bytes; terminal reuse now verifies its input and artifact SHA-256 bindings before returning a prior result.

Structured HTTP, request, console, and page errors are forbidden by default; this is an intentional user-visible policy change. Real Chromium proof covers both reference apps and denied hostile egress.
- 1.0-CRED-EGRESS credential-egress containment (#172): added action-owned canonical-origin preflight, generated once-per-test context-level default-deny HTTP(S) and WebSocket interception, Chromium CDP response-stage foreign-redirect blocking, Service Worker blocking, and stable blocked diagnostics; approved requests continue natively via `route.continue()` and unchanged responses via `Fetch.continueResponse`, a narrowly bounded same-port `localhost`/`127.0.0.1` alias admits the reference app's attested loopback redirect, and real Chromium proved 302/303/307/308 credential-bearing foreign redirects, fetch, and WebSocket attempts send no canary bytes while legitimate same-origin workflows remain runnable.

Real-Docker adversarial tests prove blocked unsafe-entry/quota diagnostics without host writes or worker OOM while preserving isolation.
- 1.0-ATTEST-TRUST Attestation trust hardening (#177): require signed non-local receipts and independent nonce, build-digest lineage, and operator origin policy while preserving real local-test reference-app handshakes.

- 1.0-SOURCE-HASH Worker source integrity (#178): replace the config-projection digest with a canonical manifest over real staged bytes, independently recompute it in the CLI, and block promotion on any worker hash mismatch; real Docker proof covers agreement and a fabricated result.

- CLI: narrow policy validation to the values the worker accepts (#104): `validateConfig` now accepts only `policy.mutation: 'leased-fixtures-only'` and `policy.externalNetwork: 'deny'`, matching what `validateWorkerSecurity` enforces at run time, and `ArxicConfig` carries both as singleton literals so a config the worker would refuse no longer typechecks. - Worker sandbox: reject a root identity in either half of `workerUser` (#101): `assertSafeSpec` now rejects the `root` name in any case and every integer form Docker parses as zero (`0`, `00`, `+0`, `-0`) in **both** the uid and the gid position, before any `docker run`. This closes more than the filed root-group case: Docker maps an _omitted_ half to 0, so `1000:` (gid 0), `:` (uid 0) and an empty `workerUser` (uid 0) previously produced a root identity and passed validation. Behaviour confirmed empirically against real Docker 29.7.1 and the official `docker run` reference. A caller-supplied non-root `workerUser` is still accepted and runs as exactly that uid:gid. `defaultWorkerUser()` and every isolation property are unchanged. Known limit, documented in code: image-local account aliases that resolve to uid/gid 0 without being named `root` (e.g. `toor`) cannot be detected without resolving against the image's account database, which would break the reject-before-any-Docker-call property.

The compile-policy rationale is narrowed to the exact reviewed `page.locator('form')` shape — `findUnapprovedNonSemanticLocators()` still rejects any other non-semantic locator in a file that already carries a rationale, so the escape hatch cannot be reused to smuggle arbitrary CSS past the gate (#89). Entry navigation resolves from the observed runtime URL rather than being derived from the state name, with later transitions keeping state-derived routes, and `url:` assertions compile to an anchored pattern (`^<escaped url>(?:[?#].*)?$`) that tolerates a query string or fragment but still fails on a different path — so a redirect to `/?message=…` passes while a wrong route does not (#87).
