## 3. `CHANGELOG.md` — entry under `## [Unreleased]` → `### security`

```
- 0.1.1-TAR-SAME-STREAM (#212): Harden worker-result extraction by quota-bounded spooling and fail-closed validation of the exact tar stream before host extraction, including PAX/GNU path extension handling; real Docker transport proof covers rejection cleanup and no host staging before rejection.
```

Trade-off: the prior design deliberately avoided materializing worker result bytes on the host. The spool now uses up to `quotaBytes` of host temporary disk (2048 MiB in the issue configuration; this checkout currently caps `resultVolume.quotaBytes` at 256 MiB) to establish same-stream atomicity; it streams directly to the file, so the heap remains uninvolved.

The validator is deliberately stricter than `tar -xf`: it requires a two-zero-block trailer and all-zero trailing record padding. Standard `tar -cf` output satisfies both constraints.
