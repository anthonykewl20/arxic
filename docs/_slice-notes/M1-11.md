## What & why

A local CLI entry point: `arxic run --config arxic.yaml` parses and validates the ADR §19 configuration, submits a run to a `RunExecutor`, streams stable diagnostics (frozen `Diagnostic` contract — the audit record, never raw model prose), and writes a run directory with ADR §20.1 observability (`run.json`, `diagnostics.jsonl`, `config.json`) alongside the orchestrator's per-stage `stages/NN.json` + `artifacts/NN.json`. This is the action/orchestration layer (charter §1): argument handling, config validation, failure classification, user-facing errors — it delegates all pipeline mechanics to the orchestrator via the executor port.

Exit-code policy (CLI-owned, fail-closed-friendly for CI): **0** = run verified + run dir written; **1** = run dir written but outcome not `verified` (observed/blocked/contradicted/hypothesized), or executor crash, or run-dir write failure; **2** = configuration/usage error (no run dir).

## Real-world proof (charter §6 — non-synthetic)

`apps/cli/src/__tests__/real-world.test.ts` builds the real `reference-auth-app`, boots it on an ephemeral `freePort()` with a per-run temp sqlite (`ARXIC_DB_PATH` → `mkdtemp`; no `ARXIC_MAILPIT_*` per the slice brief), writes a real `arxic.yaml`, and runs `runCli(['run','--config', arxic.yaml, '--out', …, '--run-id', 'm1-11-real'])`. The real pipeline runs: real attestation handshake, real sg + Tree-sitter source scan, real **PlaywrightCrawler** (real Chromium) surfacing `/`, `/login`, `/forgot-password`, default inference, real reconciliation. It then asserts a real run directory with:
- `run.json` — schemaVersion 1, §20.1 fields populated (stage checkpoints incl. a completed `attestation` stage; merged `toolVersions` — `nextjs-auth`, `tree-sitter`, `tree-sitter-javascript`, `tree-sitter-typescript`; artifact hashes; decisions; gate results; redaction; run id);
- `artifacts/05.json` — real Crawlee surface map;
- `diagnostics.jsonl` — stable `ARXIC-*` codes (each `validateDiagnostic`-valid);
- `config.json` — redacted config echo;
- honest outcome `observed` (status `partial`) — **not** `verified`, because stages 4 (#42) and 8 (#43) are not yet implemented.

The unreachable-target test points the origin at a dead port and asserts the run completes `blocked`/`failed` with a `severity: 'blocked'` attestation diagnostic, a written run directory, and **no stack trace** on stderr.

## Layering (charter §1)

`apps/cli` is **action/orchestration only**: `run.ts` = load config → classify → delegate to `RunExecutor` → write run dir; `cli.ts` = arg dispatch + user output; `config/validate.ts` = pure validation service; `run-directory.ts` = §20.1 writer service. No pipeline logic is reimplemented — `LocalRunExecutor` only maps `RunRequest` → `OrchestratorInput` and maps `RunState` → `RunResult`. `RunExecutor` is a clean DI port (no premature abstraction; one caller today, the remote-worker executor is the second).

## Known limitations / residual risk (honest)

- **In-process execution, not isolated.** `LocalRunExecutor` runs the orchestrator in this process. Worker isolation/quotas/prompt-injection containment land with #26 (`WorkerClient`-backed executor).
- **Diagnostics batch at completion.** The orchestrator exposes no progress callback, so streaming is flush-at-end today. Live streaming lands with the worker event stream (#26).
- **Verified staged tests + coverage report not produced through the CLI yet.** Reaching `verified` requires stage-4 inference (#42), stage-8 exploration (#43), and the M1-EXIT composition (#27) wiring the compiler/verifier into the run. Today the CLI run is honestly `observed`/`partial` (or `blocked`).
- **Resume assumes the same config for a reused `--run-id`.** The default `runId` is a fresh UUID per run; input-digest validation on resume is orchestrator-owned (#17). Don't reuse a `--run-id` with a changed config.
- **Some ADR §19 fields are validated but not yet enforced** (`environmentClass` beyond `local-test`, `attestationPath`, `maxRuntimeMinutes`, `requiredVerificationRuns`, `featureFlags`, `browser`, fixture/model policy) — the orchestrator/worker do not consume them yet. The CLI is forward-compatible; enforcement lands as those stages consume the fields. `target.origin ∈ allowedOrigins` and `local-test` are enforced.
- **`arxic` executable binary** is not shipped (source-only, ADR-003). The supported invocation today is the programmatic `runCli` entry; the binary lands with emit / the worker.
