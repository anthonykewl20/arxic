### Deferral and scope rationale

This remains the live-flow branch: although no package imports `@arxic/m0-pipeline` today, it is the M0 capstone real-world proof. Retirement and the published-package-set decision belong to #184/#185, not this consolidation.

Full `PlaywrightVerifier.verify()` adoption is deferred. It requires runtime evidence in the staged bundle before verification and hard-trusts the playwright-compiler nested-suite layout; the M0 capstone instead creates a flat suite with `renderFallbackSpec` and adds runtime evidence after verification. That is a chicken-and-egg transition-receipt/pre-verify-bundle problem, plus compiler-suite trusted binding work. A follow-up slice should stage the required bundle and receipts before verification, establish the compiler-suite binding, then adopt the full verifier action without changing the capstone proof's outcome, promotion, or LKG assertions.

### Classification precedence disclosure

A combined flaky-runs plus missing-required-transition result now classifies as `contradicted` (`ARXIC-VERIFY-FLAKY-RUNS`) rather than the old M0 `blocked` result. This follows canonical `classify.ts` ordering; neither result promotes. The verifier-owner follow-up is that canonical classification also evaluates flaky/app-defect before blocked-network, so mixed pass/fail runs with network errors report `contradicted` and mask the network violation. This slice does not alter that canonical behavior.
