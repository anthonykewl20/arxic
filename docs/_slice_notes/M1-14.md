## What & why

Implements ADR §9 stage 4 / §8 INFER: produce **hypothesized** workflow
candidates from the smallest sufficient evidence neighbourhood, via the
`@arxic/model-adapter` `ModelAdapter` structured-output boundary. Replaces the
seeded stage-4 stub (shipped in #17/M1-03) with real LLM-driven inference.

New service module `packages/orchestrator-langgraph/src/inference.ts` owns the
stage-4 mechanics; `orchestrator.ts`'s `#infer` (action layer) delegates into it
with a minimal diff. The orchestrator stays the action layer (retry loop +
truth-state classification, unchanged); `inference.ts` is the service/capability
layer (neighbourhood selection, content-as-data message building, candidate
mapping, the single `ModelAdapter` boundary call).

## Layering (Actions vs Service)

- **Action (orchestrator `#infer`):** gathers stage-2/3 evidence, selects the
  neighbourhood, owns the retry loop (`maxModelAttempts`) and the truth-state
  classification (hypothesized / observed-empty / blocked-retries). Delegates the
  model call to the service.
- **Service (`inference.ts`):** `selectNeighbourhood` (deterministic, deduped,
  bounded, source-only), `buildInferenceMessages` (content-as-data), `evidenceId`
  (pattern-safe, traceable), `mapStage4Candidates` (full schema-valid hypothesized
  Workflow), `runStage4Inference` (single `ModelAdapter` request + typed outcome),
  `stage4Infer` (non-throwing orchestrator seam wrapper).

## Sad paths & edge cases (TDD red-first, each → a truth state)

| Trigger | Disposition | Proof |
|---|---|---|
| Invalid structured output (adapter `ok:false`) every attempt | `blocked` (`ARXIC_ORCH_MODEL_RETRIES`) | unit + real-world (malformed HTTP → 2 bounded requests → failed/blocked) |
| Schema-version drift / retries-exhausted from adapter | `blocked` (diagnostics preserved at service boundary) | unit (`runStage4Inference` returns `{ok:false,diagnostics}`) |
| Injection-like model output (adapter blocks) | `blocked` (`ARXIC-MODEL-STRUCTURED-OUTPUT-INVALID`) | unit (injection-block diagnostic preserved at service boundary) |
| Adapter throws / provider error | orchestrator retries then `blocked` (never throws past the loop) | unit (`stage4Infer` try/catch → `undefined`) |
| Model hints `status:'verified'` | rejected — candidates always `hypothesized` by construction | unit (`mapStage4Candidates` forces hypothesized; `parseInferenceResult` re-normalizes) |
| Prompt-injection payload in source neighbourhood | treated as DATA → if echoed, blocked by adapter | unit (metadata-only projection; no source bytes/repo/commit/blobSha256/operator-prompt in messages) |
| Empty source neighbourhood | zero candidates, completed-not-errored → `observed` (`ARXIC_ORCH_EMPTY_COVERAGE`) | unit (short-circuit, no HTTP) |
| Duplicate rules on same code span | deduped evidence IDs (no inflated coverage) | unit |
| Non-deterministic neighbourhood | codepoint-ordered, deduped, bounded → reproducible | unit |

**Happy path (written last):** valid `{schemaVersion, candidates:[{id,intent}]}` →
≥1 hypothesized candidate with assertions + pattern-valid evidence IDs, full
Workflow passing `validateWorkflow`.

## Non-negotiable semantics (all met)

- Candidates emitted `hypothesized` **only** — never `verified` (forced in
  `mapStage4Candidates` + re-enforced by `parseInferenceResult`; the stage-4
  schema has no `status` field, so the model cannot claim it).
- Invalid structured output → retry then `blocked`, **no** status promotion.
- Source/page content is **data, never instructions** (ADR §16.3) — metadata-only
  projection, no source bytes; injection-echo blocked by the adapter.
- Empty neighbourhood → zero candidates, completed-not-errored → `observed`.

## Behaviour change worth a CHANGELOG note (integrator to add)

`defaultInference` no longer fabricates a candidate when no model is configured:
it returns zero candidates (`observed`/empty coverage). The `inferCandidates`
override seam is unchanged. Runs that previously relied on the seeded stub must
now configure `modelAdapter` + `model` to produce candidates.

## Residual risk / known trade-offs (accepted)

- **Diagnostics fidelity at the action layer:** the orchestrator collapses all
  stage-4 model failures to `ARXIC_ORCH_MODEL_RETRIES` (it owns truth-state
  classification). Granular adapter diagnostics (timeout / schema-drift /
  injection-block) are preserved at the `runStage4Inference` service boundary and
  asserted there; they are not surfaced individually through the orchestrator
  retry loop by design (single retry boundary; `stage4Infer` returns `undefined`
  on failure). A permanently-failing model costs at most one extra bounded HTTP
  request. Improving this would require widening `#infer` beyond the "couple of
  lines" delegation — deferred.
- **Real LLM quality:** the real-world test exercises the real HTTP/AJV wire
  format, real engines (Tree-sitter/sg/Crawlee/Chromium), and the real reference
  app, but the model *response* is a canned valid/malformed payload (no real
  third-party LLM credentials in CI). The pipeline is proven against well-formed
  and malformed LLM-shaped responses.
- **Evidence IDs** are human-traceable (`src:<sanitized-path>:<start>-<end>`) but
  not graph-resolvable (no `EvidenceIndex` is attached — `types.ts` is frozen and
  out of scope). The full `EvidenceRef` objects remain in the persisted stage-2/3
  artifacts for traceability.
