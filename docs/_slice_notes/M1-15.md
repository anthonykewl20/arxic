## What shipped

The ADR §8 TARGETED / §9 stage-8 loop is now real:
**plan → policy check → human approval → explore → journal → budget → normalize to Workflow IR.**

- `planExploration()` turns candidate `Workflow` transitions into deterministic
  intent plan entries, each tagged with a policy action + `ActionClass`
  (`navigation`→read-only, `form-submit`→reversible-mutation,
  `delete-user`→destructive, `file-write`→external-side-effect).
- `runExploration()` is the orchestration loop: for each step it authorizes
  origin + action class **before** any execution via the `@arxic/policy-engine`
  `PolicyEngine`; privileged/external/destructive steps interrupt for a
  recorded human approval (an LLM may never self-approve); a step budget
  governs progress; read-only steps are executed by the real
  `PlaywrightExplorationDriver`; observations are normalized into canonical
  runtime `EvidenceRef`s carrying a real `accessibilitySnapshotSha256`.
- The LangGraph orchestrator `#explore` stage now delegates into
  `exploration.ts` (`defaultExploration`) with full run context (origin,
  runId, appBuildDigest, budget) instead of the deterministic stub.

## Disposition (truth states — ADR §2)

Exploration may originate **at most `observed`** — it never assigns `verified`
(only the stage-10 deterministic verifier may).

- Read-only plan observed → **observed** (real accessibility snapshots).
- Forbidden action / origin denied → **blocked**.
- Destructive or external step without recorded human approval → **blocked**
  (`ARXIC-EXPLORATION-APPROVAL-DENIED`); proceeds only when a recorded
  `HumanApproval` is supplied.
- Human denied (approval withheld on resume) → **blocked**.
- Budget exhausted mid-plan → **blocked** gracefully (never a crash, never a
  silent pass).
- Locator/origin drift → **blocked**, never silently passed.
- Required transition not observed → **observed** (`ARXIC-EXPLORATION-TRANSITIONS-UNOBSERVED`).

## Layering (charter §1)

- **Action / orchestration** (`packages/orchestrator-langgraph/src/exploration.ts`):
  owns the plan→policy→approval→budget→journal→normalize loop and all failure
  classification / dispositions. New module-local diagnostics
  `ARXIC-EXPLORATION-*` (validated through the frozen `validateDiagnostic`,
  loop-closed in `exploration.test.ts`).
- **Service / capability block** (`packages/playwright-agent-adapter/src/exploration-driver.ts`):
  `PlaywrightExplorationDriver` launches real Chromium, drives read-only
  navigate/snapshot steps, captures the real accessibility tree (CDP
  `Accessibility.getFullAXTree`) + optional Playwright trace + named
  screenshots. Pure mechanics; returns structured results, no diagnostics of
  its own.
- `orchestrator.ts` change is minimal and confined to the permitted regions:
  only `#explore`, `defaultExploration`, and the `explore` option input type.
  The frozen `ExplorationResult` shape (`types.ts`) is unchanged.

## Sad paths proved (TDD red-first — exploration.test.ts, FakeDriver at the browser boundary)

1. forbidden / unknown policy action → `blocked` (`ARXIC-EXPLORATION-FORBIDDEN`), nothing executed.
2. destructive without recorded approval → `blocked` (`ARXIC-EXPLORATION-APPROVAL-DENIED`).
3. budget exhausted mid-plan → `blocked` (`ARXIC-EXPLORATION-BUDGET-EXHAUSTED`); never throws.
4. budget missing (zero) → `blocked`.
5. origin/locator drift → `blocked`, not silently accepted (`ARXIC-EXPLORATION-ORIGIN-DRIFT`).
6. required transition unobserved → `observed` only (`ARXIC-EXPLORATION-TRANSITIONS-UNOBSERVED`); never `verified`.
7. failed required browser step → `blocked` (`ARXIC-EXPLORATION-STEP-FAILED`).

Happy path (last): read-only navigation + successful snapshot → `approved:true`
with a runtime `EvidenceRef` whose `accessibilitySnapshotSha256` matches the
captured tree.

## Real-world proof (charter §6 — non-synthetic)

`exploration-real-world.test.ts` drives **real Chromium** against the real
`reference-auth-app` (built + booted on an ephemeral port, per-run temp sqlite
via `ARXIC_DB_PATH`→`mkdtemp`, reset+seed via the real app API; no
`ARXIC_MAILPIT_*`). All three issue acceptance criteria pass for real:

- **Read-only within budget → observed with real accessibility snapshots.**
  Real Chromium navigates `/login` and records a runtime `EvidenceRef` with a
  64-hex `accessibilitySnapshotSha256` and a real `browserVersion`.
- **Destructive pauses/blocks until approval recorded.** A destructive intent
  with no approval → `blocked` (`ARXIC-EXPLORATION-APPROVAL-DENIED`); with a
  recorded `HumanApproval` the policy gate authorizes it.
- **Budget exhaustion blocks gracefully.** `budget:0` → `blocked`
  (`ARXIC-EXPLORATION-BUDGET-EXHAUSTED`), no browser launched, no crash.

Evidence artifacts (evidence-driven-testing skill / ADR §15), produced by the
read-only real-world test and attached to the PR + issue:
- `exploration-trace.zip` — Playwright trace of the real exploration.
- `step-00-observe-route-login.png` — named full-page screenshot of `/login`.
- Observed Chromium accessibility SHA-256 prefix: `572fa81d921f`.
