### The BookStack 9-collisions defect — resolved

DG-05 deferred provider-include prefix resolution with "9 URI collisions vs
web rows stand". Two findings at DG-06:

1. **The defect class is fully resolved.** With the provider context composed
   (`Route::group([…'prefix' => 'api'…], … require base_path('routes/api.php'))`
   at `app/App/Providers/RouteServiceProvider.php:72`), all api rows are
   emitted under `/api/…` and ZERO cross-file key merges remain. Without the
   resolution the same fusion reports the merges as structured
   `ARXIC-INVENTORY-URI-COLLISION` observations — visible, never silent.
2. **The honest collision count is 19, not 9** (fusion-summary.json). The DG-05
   note counted raw `(method, uri)` pairs; the fusion key algebra also
   collapses distinct parameter names (`/books/{id}` vs `/books/{bookSlug}` →
   `DELETE /books/:param`), which adds 10 more cross-file merges of the same
   defect class. Both numbers describe the same root cause; the inventory
   reports the fusion-key truth.

### koel includes — honestly unresolved, by shape

- `app/Providers/RouteServiceProvider.php:16` includes a route file whose path
  is **computed at runtime** (`sprintf` version-aware loader) → no literal
  path → stays a visible gap (correct).
- `app/Providers/BroadcastServiceProvider.php:14` includes
  `routes/channels.php` (0 routes, `Broadcast::channel` registrations only).
  In this evidence run the provider file is not supplied to the reader, so the
  gap stays visible as "provider file unavailable". In the pipeline the
  provider IS read from the repository; with no provable enclosing
  `Route::group` the resolver still leaves the gap visible (an unproven
  context is never defaulted to an empty prefix — conservative by design).
